The models and why they were chosen

The problem is binary classification on tabular data with imbalanced classes. Three families were compared, from the simplest to the most flexible:

  • Logistic Regression: a linear model with a probabilistic interpretation. It is fast, tiny and easy to explain, and it is the reference of the comparison.
  • Random Forest: an average of many decision trees. It captures non-linear relations and interactions without scaling the data.
  • XGBoost: gradient boosted trees, very effective on tabular data, with class imbalance handled by a positive class weight.

The three models read the same {{ d.n_model_features }} features and use the same split, preprocessing and cross-validation. A single command (python -m ml.train) trains all of them, so nobody retrains a model separately and the pages of the application only display its results.

Decisions informed by the domain

  • Class imbalance. Defaults are a minority, so the models weight the default class and the recall of that class is a selection criterion, because missing a defaulter is the costly error.
  • Ranges. The values of the form are clipped to the ranges seen in the dataset ({% for column, range in d.clip_ranges.items() %}{{ column }} {{ range[0] }} to {{ range[1] }}{{ ', ' if not loop.last }}{% endfor %}), so the models never receive values they were not trained on.
  • Units. The dataset income is annual, so the monthly income of the form is multiplied by 12; the debt-to-income ratio of the form is a percentage and the model uses a ratio.
  • Protected attributes. None is added. The age is used and audited by age range (Phase 4).
  • Deployment constraints. The hosting plan has little memory, so the models are small (the artifacts stay under 20 MB) and the application keeps at most one model loaded.
