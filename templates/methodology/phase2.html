Selection and justification of the features

The models use the {{ d.n_model_features }} dataset columns that the application form asks for, so that the application and the model stay consistent: {{ d.model_features|join(', '|safe) }}.

  • Why not InterestRate. The lender sets the interest rate after assessing the risk, so using it would feed the decision into the model. It is also not a field of the form.
  • Why not Education, MaritalStatus, HasMortgage, HasDependents, LoanPurpose and HasCoSigner{% if r %} (and the {{ d.n_unused_predictors }} unused predictor columns in total){% endif %}. The form does not ask for them and some of them are sensitive. The price is a lower ROC AUC than a model that uses every column.
  • Protected attributes. Gender is not in the dataset and no protected attribute is added. The age is used and its effect is analysed in Phase 4.
  • Income. The dataset income is annual (it ranges from {{ '{:,.0f}'.format(r.before.outliers.Income.min) if r else '...' }} to {{ '{:,.0f}'.format(r.before.outliers.Income.max) if r else '...' }}), so the application multiplies the monthly income of the form by 12 before sending it to the model.

Feature engineering. There is none beyond unit conversions (monthly to annual income, years to months of employment, percent to ratio of the debt-to-income ratio) and clipping of the form values to the ranges seen in training, so that the models never receive values they were not trained on.
